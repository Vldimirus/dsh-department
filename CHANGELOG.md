# Changelog

## 0.3.0
- **Обязательная стадия дизайна** (`design` → `design_review`): без утверждённого `design.md`
  исполнение не начинается.
- Гейт дизайна: 3+ референса со ссылками, разделы макета/палитры/типографики и хотя бы
  один скриншот/эскиз в `references/`.
- **`dept_reference`** — дизайнер сохраняет картинку или скриншот страницы в `references/`.
- **`dept_design`** — дизайнер читает design.md, референсы и отметки человека.
- Вкладка **«Дизайн»**: галерея референсов, «♥ Нравится» / «✗ Не то» с комментариями.
- Дизайнер: `reasoning: high`, инструменты исследования.


## 0.2.3
- `dept_health` не считает руководителя активной работой — отдел больше не засыпает
  с ложным «working» после коммита этапа.
- Сторож антизалипания: порог простоя 5 минут, кулдаун 10 минут.


## 0.2.2
- Утверждение ТЗ/концепции автоматически будит руководителя промтом по стадии.
- «Запустить отдел» отправляет промт под текущую стадию (обсуждение, ТЗ, концепция, план, релиз).


## 0.2.1
- Создание задачи: авто-инициализация git, автоподстановка ID/названия, авто-определение `npm test`.
- Выбор папки проекта: обзор каталогов, список известных корней.
- Создание задачи автоматически запускает чат руководителя с готовым промтом.
- Кнопка «Запустить отдел» для уже созданной задачи.
- Удаление задачи (перемещение в `docs/department/.trash`).


## 0.2.0
- **Обсуждение задачи**: `discussion.md` (цели, не-цели, пользователи, ограничения, риски, вопросы, решения).
- **Гейт утверждения**: ТЗ нельзя утвердить при открытых вопросах; концепция — без двух вариантов.
- **ТЗ и концепция в любом порядке**, запуск проекта только после утверждения обоих.
- **Стадия release**: `dept_handover` собирает `delivery/` (RUN.md, MANUAL-QA.md, CHANGELOG.md, RELEASE.md + копии документов), без неё `done` недоступен.
- **Встроенный пиксель-редактор**: трафарет, сохранение в проект, передача художнику.
- **«Отдел вкл/выкл»** и **«＋ Задача»** в панели.
- Ужесточены переходы: из ревью нельзя проскочить без утверждения человеком.
