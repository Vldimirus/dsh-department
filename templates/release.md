# Шаблон задачи «Подготовка к релизу»

Релиз — штатная фаза после `done`: продукт упаковывается, документируется и передаётся человеку.

## 1. Пакет

- [ ] Собрать артефакт из готовой ветки: `release/<продукт>-<версия>/`
- [ ] Только необходимое для запуска (без тестов, процессов и мусора)
- [ ] Архив `release/<продукт>-<версия>.zip`
- [ ] Проверить запуск в чистом окружении (сервер/команда из документации)

## 2. Документация пользователя

- [ ] `README.md`: что это, как запустить, управление/основные действия
- [ ] `MANUAL-QA.md`: чек-лист ручного тестирования по системам
- [ ] `CHANGELOG.md`: что вошло в версию
- [ ] Известные ограничения и как сообщить о баге

## 3. Проверка

- [ ] `npm test` / тесты проекта — зелёные
- [ ] `dept_verify` — PASS
- [ ] Бета-тест: пройти сценарии из чек-листа, баги через `dept_bug`
- [ ] Критичные баги исправлены или внесены в backlog с причиной

## 4. Версия и фиксация

- [ ] Версия в документации и changelog
- [ ] `dept_commit` с тегом `v<версия>`
- [ ] Тег отправлен в remote

## 5. Передача

- [ ] Где забрать (путь/ссылка/архив)
- [ ] Как запустить
- [ ] Что проверять руками в первую очередь
- [ ] Итоговый отчёт `report.md`

## Критерии приёмки

- человек может забрать артефакт и запустить без подсказок;
- документация отвечает: запуск, управление, ограничения;
- чек-лист покрывает все ключевые системы;
- тесты и аудит зелёные; тег проставлен и отправлен.
